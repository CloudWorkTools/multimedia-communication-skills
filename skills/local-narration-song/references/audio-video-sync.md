# 已接受配方與音畫同步

## Resume-CV 成功案例

2026-10-08，一個完整教學歌曲案例由使用者接受。原稿 41 句、289 字，模型輸入只轉簡體，字幕維持繁體。原生男聲、木吉他民謠流行；caption 引導 90 BPM／C major／4/4，搭配稀疏鋼琴、貝斯與刷鼓。速度、調性與和弦不是實測認證。發布包只包含可重用流程與預設，不包含原專案歌詞、影片、姓名或本機素材。

重現自己的歌曲時，保存精確 `生成請求.json`、`生成設定.json`、原始 WAV／replay JSON 與檢查紀錄；不要從摘要猜歌詞或參數。

完整版本用 duration 180（生成上限）、steps 30、seed 與 lm_seed 42、lm_cfg 1.5、lm_top_k 50、dit_cfg 1.7、兩種 batch 1、peak_clip 0、wav32；CLI max-seq 8192。精確 runtime 與權重版本見 local-workflow.md。實際 WAV 103.201 秒、44.1kHz stereo，影片 103.233 秒、1080p／30fps。短版預設 duration 60 不適用於直接重現完整曲。

修訂 caption 取消催促緊湊／三分鐘內的語句，要求每段只唱一次、最後一句後自然收尾；最後四句標 `[Outro]`。針對本曲姓名、方形、圓形、試讀強調聲母，其他歌詞只提示真正有疑點的詞，不複製無關詞。參數不變，讓模型自行結束，沒有剪掉重複唱句或加速人聲。

使用者接受完整成品不會抹掉獨立 ASR 的字音疑點；保留原始辨識、check_song 的 review_required 與接受紀錄。不能聲稱代理直接聽過、每字唱對或所有新歌都會同樣成功。

## 先定音訊，再定影片

以下同步原則也適用於已有朗讀旁白；本 skill 不因此負責生成一般 TTS。

1. 確定最終混音，保留原始 WAV，再做整曲增益與交付格式。記錄來源檔、雜湊、實際 sample rate／duration。不要用預定長度、caption BPM 或舊影片秒數當正式時間軸。
2. 對全曲混音與診斷乾聲各做無目標歌詞提示的 ASR。先查漏唱、加唱、重複、倒序，再定位。它們是同一 ASR 模型的兩次辨識，不能稱兩個獨立模型。低可信樂句用含上下文的裁切重辨，保留原始輸出及 offset；全曲時間等於裁切時間加 offset。
3. 依實際詞界、換氣、樂句與聽辨修正字幕時間。整詞保留整詞時間，不能平均分配多字詞。近同音匹配只能提供定位錨點，強制對齊不能補出未唱的字。若首字辨錯，查實際詞界，避免把字幕推遲到第二個字才顯示。
4. 確保時間單調、不重疊、位於音訊範圍內；句間休止與尾奏保留。若影片有固定時長，先確認能否延長／調整內容，不能偷偷加速或切尾音。
5. 讓畫面事件跟隨對應語意句，不只跟段落起點。例如本案講到「雙線親密」才揭露雙線語意，先唱戒指／婚姻再揭露愛心／親密，保留人物姓名與前後關係。停頓仍保留可理解的畫面，末句及尾奏不被提早截掉。
6. 將確定的 WAV 複製到影片實際讀取的 audio asset，核對雜湊、audio 起點與有效長度。重新生成、剪接、補靜音、換混音或重採樣後，都重新核對相關句界、畫面事件與輸出音軌；不能沿用另一個 seed／模型的錨點。

重用專案的字幕定位與影片建置工具前，核對歌詞句數、鏡數與語意揭露規則；本案曾固定 41 句／10 鏡，這不是任意歌曲的通用假設。影片 runtime 依目前專案 README 的版本、離線與遙測邊界執行；本發布包未包含該案例的影片建置工具。

## 核對渲染後的 MP4

- 先做瀏覽器時間定位檢查：每句只顯示預期字幕，圖像揭露順序正確，往前／往後 seek 結果一致。對關鍵語意轉換檢查前後一幀，避免只有中點對但交界錯。
- 再解碼實際 MP4：抽取所有字幕的中點畫面與每鏡代表畫面，檢查字句、遮擋、畫面語意；不能只看 HTML 或渲染前預覽。本案保留 41 句與 20 個代表畫面。
- 將 MP4 音軌與來源 WAV 解碼成同取樣率 PCM，在開頭、中段、間奏後及末尾做互相關／偏移比較。片長相同也可能放錯音檔；只核對開頭會漏掉後段累積漂移。來源内容若刻意改過，先保存並說明處理，不能任意降低相關門檻。
- 本案在 1、20、40、60、80、98 秒比較 2 秒窗口，相關 0.9954–0.9995、偏移 0 秒（16kHz 格）。當次檢查門檻為相關 >0.97、偏移 <20ms；這是同源音訊經 AAC 編碼的案例門檻，不能套成所有製作的品質標準。
- 影片長度容許幀取整：本案 30fps 尾幀使影片多約 32ms。瀏覽器 duration 比 metadata 的檢查用 1ms 容差處理浮點顯示差異；這不代表放寬實際音畫偏移。check_song 的字幕時間容差亦不能拿來取代音軌同步檢查。
- 將技術核對、ASR 疑點與使用者聽辨分開記錄。交付可播放 MP4、歌曲、字幕、時間軸、精確設定與檢查紀錄；使用者採用後保留原檔，外發檔可用題名另存。

## 曾犯錯誤與修正

| 錯誤／現象 | 後續處理 |
| --- | --- |
| ACE／SoulX 前段好、長間奏後人聲與伴奏異常 | 不再用舊模型作預設；MiniMax 原生歌手優先。已刪舊權重，共用 CUDA／辨識／分軌環境保留。 |
| 第一完整 MiniMax 約 156 秒，111 秒後重複後段 | 保留失敗候選，修訂收尾提示與 Outro；沒有偷偷剪除重唱段。 |
| 裁切 48–69 秒辨出無關節目文字 | 以 44–76 秒上下文及混音重辨，保留異常紀錄與 offset；ASR 幻覺不能直接當漏唱。 |
| 289 字數相同／近同音對齊看似成功 | 仍逐句列出字音疑點，字幕正確不等於歌聲正確。 |
| 舊時間軸、錯誤詞界或只檢查片頭 | 最終音訊重新定位，語意畫面跟句，實際 MP4 全片多點檢查。 |
| 浮點 duration 嚴格等號導致誤報 | 採小容差處理數值差異，另核對音軌偏移與尾幀取整。 |
